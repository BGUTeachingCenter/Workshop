## מה הושלם

### 1. שוויון מגדרי בכל המלל ✅
כל הטקסט עבר מלשון נקבה ל**לשון רבים** מכלילה (חשבי→חשבו, מתחילות→מתחילים,
מנחָה→מנחה, משתתפת→משתתף/ת). נבדק: אפס שאריות + בדיקה חיה.

### 2. מפגש 1 - סגור ✅
9 יחידות, מבנה שלם, נבדק חי (progressive disclosure, תצוגת משתתף/מנחה).

### 3. Firebase - חי ועובד ✅
האתר רץ מול Firebase אמיתי (`BACKEND="firebase"` ב-`app/config.js`), החליף את
ה-mock המקומי. התחברות אמיתית, נתונים משותפים בין מכשירים, ומנחה משותף - נבדק
ועובד (כניסת מנחה מציגה שקפים).
- **כניסת משתתפים:** שם + אימייל + **סיסמת הסדנה** המשותפת (`WORKSHOP_PASSWORD` ב-config).
- **כניסת מנחים:** רק בכפתור **"כניסת מנחה עם Google"**. מנחה = אימייל מהרשימה +
  אימייל מאומת + כניסת Google (שלושתם נאכפים ב-`firestore.rules`). הסיסמה המשותפת
  גלויה לכל דפדפן ולכן לא מקנה הרשאת מנחה, גם עם אימייל של מנחה.
- פרויקט Firebase: `gen-lang-client-0866732986` (Firestore + Email/Password + Rules).

#### ➕ איך מוסיפים הרשאת מנחה למרצה
**בלחיצת כפתור, בלוח הניהול:**
- סימון שורה בטבלת המעקב ← **"הפיכה למנחה"**, או
- **צוות ההנחיה** ← הקלדת אימייל ← **"הוספת מנחה"** (גם למי שעוד לא נרשם).
- "הסרה" מבטלת. נשמר במסמכים `admins/{email}` ב-Firestore; רק מנחה יכול לשנות.

ההרשאה פועלת רק בכניסה ב**"כניסת מנחה עם Google"** עם חשבון Google מאומת של אותו אימייל
(כניסה בסיסמת הסדנה נשארת משתתף/ת). אם כבר היה חשבון סיסמה באתר, Google מתחבר לאותו חשבון והנתונים נשמרים.

**בעלים** (`inbaltsa@post.bgu.ac.il`) קבועים בקוד ובכללים ואי אפשר להסיר אותם מהממשק - כדי שאף פעם לא יינעלו בחוץ.
להוספת בעלים נוספים: אותו אימייל (אותיות קטנות) ב-`app/config.js → ADMIN_EMAILS` **וגם** ברשימה ב-`isAdmin()` שב-`firestore.rules`, ואז פרסום הכללים בקונסולה.

דרישות בקונסולה: Google מופעל תחת Sign-in method, וכתובת האתר ב-Authorized domains.

### 4. מפגש 2 - בפיתוח פעיל 🔧
10 יחידות. נוספו/שונו לאחרונה (ישירות על main): יחידת **Copilot** (`m2-u3b`,
אופציה חינמית) + טאב Copilot ביחידת השמירה, **מילון מושגים נפתח** (מפגש 2-3),
שלב אישור התחברות ביחידת חיבור ה-AI, והוסר הטאב של **Gemini**.
יחידת ה-Commit (`m2-u1b`, "נקודת שמירה: Commit") קיימת בין GitHub ל-Codespaces.

**סדר מפגש 2 (מנובמבר 2026):** כולם מתקינים עוזר AI בטרמינל של ה-Codespace (`m2-u3`, או Copilot ב-`m2-u3b`),
ומיד אחר כך מי שעם Claude / ChatGPT עובר לעבוד מהאתר (`m2-u3c`: claude.ai/code, chatgpt.com/codex) - Copilot נשאר ב-Codespace.
לכן Pages (`m2-u5`) הוקדם לפני לולאת הפיתוח: מהאתר רואים שינויים רק באתר החי (PR ← Merge ← רענון).
מפגש 3 מותאם לשני המסלולים: מהאתר בודקים באתר החי (PR ← Merge ← רענון), ב-Codespace בתצוגה המקדימה (בלוק CHECK אחרי כל בקשה).

### 5. מפגש 3 - מלוטש, ממתין לבדיקת המנחה 🔍
9 יחידות (8 + בונוס), עדיין לא הועבר בלייב. ההחלטות המרכזיות:
- **סדר השכבות:** Authentication (`m3-u4`) → Firestore (`m3-u5`) → Rules (`m3-u6`).
  קודם "מי המשתמש", ואז שומרים ישר תחת ה-uid - בלי לבנות מחדש את השמירה.
- **התחברות עם Google** (popup) כברירת מחדל. הנקודה הרגישה: **Authorized domains**
  (`username.github.io` + כתובת התצוגה המקדימה של ה-Codespace).
- **מבנה נתונים אחיד:** אוסף `responses`, מסמך לכל סטודנט ששמו ה-uid. כללי האבטחה
  ניתנים מוכנים (בלוק `code`), והעוזר רק מתאים ומסביר. המרצה רואה תשובות בקונסולה;
  מסך מרצה באפליקציה הוא יחידת הבונוס (`m3-u9`).
- `m3-u1` היא יחידת חזרה לפרויקט (פתיחת ה-Codespace הקיים), ו-`m3-u2` נפתחת בבלוק
  `recall` שמציג את התשובה שהמשתתף כתב במפגש 1 - הדגמה חיה של "בסיס נתונים".
- **לבדוק בהרצה יבשה לפני המפגש:** שמות הכפתורים בקונסולת Firebase (משתנים), והתחברות
  Google מתוך התצוגה המקדימה של Codespaces.

### 6. קבוצות ומעקב בלוח הניהול ✅
- **ניהול ← פתיחת קבוצה חדשה**: נותנים שם, והקבוצה הופכת ל"פעילה". מי שעדיין לא משויך לקבוצה ונכנס בזמן שהיא פעילה - מצורף אליה; מי שכבר משויך נשאר בקבוצה שלו. העברה בין קבוצות: סימון שורות בטבלה ← "העברה" (כולל "קבוצה חדשה…" שלא הופכת לפעילה).
- בבחירת קבוצה רואים מי נכנס, מתי בפעם האחרונה, ומה סומן ב"בדיקה עצמית" בכל יחידה (✓ = הכול סומן, מספר = כמה פריטים; ריחוף/לחיצה מציגים את הפריטים).
- "סיום הקבוצה הפעילה" עוצר צירוף; "הפיכה לקבוצה הפעילה" מחזיר קבוצה קודמת.
- **דורש את firestore.rules המעודכנים** (מנחה קורא את progress; אוסף groups רק למנחה). בלי זה הלוח מציג הודעה ולא נשבר.

## איך רואים את האתר
אפליקציית HTML סטטית עם ES Modules - חייבים לשרת דרך http (לא file://):
```
git checkout main && git pull
python3 -m http.server 8000      # הפורט בדפדפן = הפורט כאן!
```
← `http://localhost:8000` + **רענון קשיח `Ctrl+Shift+R`** (ES Modules נתקעים ב-cache).
כניסה: שם + אימייל + סיסמת הסדנה. אימייל מרשימת המנחים = תצוגת מנחה עם שקפים.
