## מה הושלם

### 1. שוויון מגדרי בכל המלל ✅ (הושלם, נבדק, נדחף)
כל הטקסט בסדנה עבר מלשון נקבה ל**לשון רבים** מכלילה:
- פעלים בגוף שני → רבים (חשבי→חשבו)
- "אנחנו" הקבוצתי → זכר-רבים (מתחילות→מתחילים)
- תפקידים: מנחָה→מנחה, משתתפת→משתתף/ת
- קבצים: `content/meeting-1/2/3.js`, `app/views/*`, `app/render/blocks.js`,
  `README.md`, `docs/sync.md`, `docs/meeting-2/3-screenshots.md`, `handouts/memory-card.html`
- נבדק: סריקה כלל-מאגרית = אפס שאריות נקבה; בדיקה חיה בדפדפן (משתתף + מנחה).

### 2. מפגש 1 - סגור ✅ (נבדק חי)
9 יחידות, מבנה שלם, אין מזהים כפולים, אין סימוני טיוטה.
נבדק חי: progressive disclosure עובד, תצוגת משתתף מול מנחה תקינה.

### 3. מפגש 2 - בעבודה 🔧
- **יחידה 1** (`m2-u1`, פותחים פרויקט ב־GitHub): הוסר "commit" משלב ההעלאה -
  עכשיו רק יוצרים פרויקט + מעלים קובץ.
- **יחידה חדשה** (`m2-u1b`, "נקודת שמירה: Commit") נוספה בין GitHub ל-Codespaces:
  מושגית - מה זה ניהול גרסאות, שעושים commit אחרי שינוי, ואיך זורקים שינויים
  ולחזור ל-commit האחרון (רשת ביטחון). ממתינה לאישור סופי של הניסוח.

## הבא בתור (סשן הבא)

שיטת עבודה מוסכמת למפגש 2: **עוברים יחידה-יחידה, שקף-שקף**, בודקים תוכן,
ולכל יחידה מחליטים אם צילום-מסך שווה כעוגן (המנחה מדגימה בלייב; הצילום הוא
לזיכרון בהמשך). מעדכנים את `docs/meeting-2-screenshots.md` תוך כדי.

1. לאשר/לחדד את הניסוח של יחידת ה-Commit החדשה (`m2-u1b`).
2. להמשיך ל**יחידה 2 · Codespaces** - מועמד חזק לצילום: מפת שלושת האזורים של VS Code.
3. להמשיך ליחידות הבאות: u3 (חיבור AI), u4 (פיתוח), u4b (שמירת גרסאות),
   u5 (GitHub Pages), u6 (SCORM), u7 (סיכום).
4. **כשמגיעים ל-u4b** ("שומרים גרסאות"): לצמצם חפיפה עם יחידת ה-Commit החדשה -
   u4b פותחת גם היא בשקף "מה זה ניהול גרסאות?" עם אותה אנלוגיית 'גרסה_סופית_2'.
   כדאי שתתמקד במנגנון (commit + push + branch + PR עם הכלי).

## איך רואים את האתר (תזכורת)
אפליקציית HTML סטטית עם ES Modules - חייבים לשרת דרך http (לא file://):
`python3 -m http.server 8000` בתיקיית הפרויקט ← `http://localhost:8000`
(מסך כניסה ראשון; אימייל עם `+admin` = תצוגת מנחה עם השקפים).
