לא רואים את השינוי? רענון קשיח

אחרי פרסום או עדכון, הדפדפן מרבה להציג גרסה ישנה מהזיכרון (cache). רענון רגיל לא תמיד מספיק — עושים רענון קשיח, שמתעלם מהזיכרון וטוען מחדש:

WindowsCtrl + Shift + R
MacCmd + Shift + R

עובד לאתר ב־GitHub Pages, לאפליקציה עם Firebase, וגם לקובץ מקומי. חלופה: Ctrl/Cmd + F5. עדיין ישן? נסי חלון פרטי.

כאן מפרסמים את כללי האבטחה שלמטה.

כללי אבטחה — נקודת פתיחה להעתקה
Firestore · Security Rules 
// כל אחד ניגש רק למסמכים שה־uid שלו מופיע בהם.
// עוזר ה־AI יתאים את השדות למבנה של הכלי שלך.
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{collection}/{docId} {
      allow read, write: if request.auth != null
        && request.auth.uid == resource.data.uid;
      allow create: if request.auth != null
        && request.auth.uid == request.resource.data.uid;
    }
  }
}
לזכור
  • "מצב בדיקה" פתוח לכולם — וזמני. ההגנה האמיתית היא בכללי האבטחה.
  • ה־firebaseConfig אינו סוד. אין טעם להסתיר אותו; להשקיע בכללים.
  • כל נתון נשמר תחת ה־uid של המשתמש — כך הוא "שייך" רק לו.
  • בודקים שההגנה עובדת: להיכנס כמשתמשת אחרת (חלון פרטי) ולוודא שלא רואים נתונים של אחרת.
רשת ביטחון · משהו נשבר?
אם עוזר ה־AI קלקל משהו — אף פעם לא נתקעים. חוזרים לגרסה שעבדה.
  1. הכי פשוט וללא סיכון: בקשי מעוזר ה־AI — "בטל את השינוי האחרון" או "חזור לגרסה הקודמת שעבדה".
  2. כל commit ששמרת הוא נקודת חזרה — ב־GitHub אפשר לחזור לכל גרסה קודמת בכל רגע.
  3. לזרוק הכול ולחזור לשמירה האחרונה (בטרמינל):
Hard resetgit reset --hard

⚠️ מוחק כל שינוי שלא שמרת ב־commit מאז. משתמשים בזה רק כשבאמת רוצים לוותר על מה שהשתנה מאז השמירה האחרונה. כל מה ששמרת ודחפת (push) ל־GitHub — בטוח ולא נמחק.
